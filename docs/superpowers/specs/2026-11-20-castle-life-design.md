# 城堡生活（暫名）— 設計文件

## 1. 意圖與動機

使用者想實際動手玩 **WebGPU**，選了一個好玩的題材：一款**原創**的中世紀城堡生活遊戲，玩法氛圍受「騎馬與砍殺」這類遊戲啟發，但**不做戰爭**。重點是在城裡生活：逛市集買馬買武器、打競技場、到城主府跟一位女子聊天培養感情，最後求婚、結婚。

這是個人娛樂專案，成功標準是「好玩、想一直玩下去」，以及確實用到 WebGPU（3D 渲染＋瀏覽器內 AI 對話都跑在 GPU 上）。

## 2. 目標 / 非目標 / 反目標

**目標**
- 3D 第三人稱，在一座城堡城鎮內自由走動。
- 市集：武器鋪（買武器）、馬廄（買馬）。
- 個人裝備畫面：看得到角色身上的裝備與擁有的馬。
- 買來的武器實際顯示在角色手上，並在競技場使用。
- 馬可以騎：在城裡上馬／下馬、騎馬移動。
- 競技場：**步戰**，簡單動作制（左鍵揮砍、右鍵格擋、閃避），對手一個一個上、越後面越強，贏了拿獎金。
- 城主府：一位女子，**自由打字聊天**，由瀏覽器本機 AI 模型（WebLLM, WebGPU）扮演；好感度提升到門檻後可求婚，成功後結婚。
- 結婚後播婚禮過場，之後可繼續在城裡生活，她也在城裡（可繼續聊天）。
- 進度存檔，下次打開可接續。

**非目標（這一版不做）**
- 戰爭、行軍、大地圖、多座城。
- 騎馬戰鬥（競技場只打步戰；之後可再加）。
- 多人連線。
- 多位可追求對象（只有一位）。

**反目標（就算技術上能動也算失敗）**
- 使用騎砍的任何素材、名稱、陣營、角色或地名；看起來像騎砍的仿製品。
- 一句甜言蜜語就能直接結婚——好感度必須是「努力爭取來的」，由遊戲規則把關，不完全交給 AI。
- AI 模型還在下載時整個遊戲卡死不能玩。
- 她的人設崩壞（突然變成助理口吻、講英文、講簡體）卻沒有任何防護。

## 3. 限制

- **執行環境**：Windows 11、Chrome（需支援 WebGPU）。顯示卡規格未確認，需在載入時偵測 WebGPU 與可用記憶體，對話模型挑選要以一般筆電 GPU 跑得動為準。
- **3D 畫面與 AI 模型共用同一張 GPU**，生成回覆時畫面不能掉到不能玩。
- **素材只用 CC0（公眾領域）授權**的低多邊形中世紀素材包（如 Quaternius、KayKit）。每個素材的來源與授權記錄在 `CREDITS.md`，下載時再次確認授權。
- **本機網路環境**：Avast 會攔截 HTTPS，npm/Node 指令要加 `NODE_OPTIONS=--use-system-ca`；curl 加 `--ssl-no-revoke`。瀏覽器端（Chrome）從 Hugging Face 下載模型不受影響。
- **交付**：本機專案，用 Vite dev server 啟動、Chrome 開啟遊玩；不發佈到任何線上服務。
- 專案位置：`C:\Users\burton.wei_smartdail\Desktop\Burton\MyGithub\castle-life\`。
- 遊戲內文字一律**正體中文**。

## 4. 做法比較（Approaches）

| 做法 | 內容 | 取捨 |
|---|---|---|
| **A. Three.js（WebGPURenderer）＋ WebLLM** ✅ 採用 | 最成熟的網頁 3D 函式庫；GLTF、骨架動畫、裝備掛點都有現成支援；無 WebGPU 時自動退回 WebGL。WebLLM 專門用 WebGPU 跑 LLM。 | 力氣能花在玩法與手感；需要自己組角色控制、碰撞、UI。 |
| B. Babylon.js | 功能完整的遊戲引擎，內建物理、角色控制。 | 較厚重，客製要順著它的架構；與 WebLLM 搭配範例少。 |
| C. 純手寫 WebGPU | 每一步 GPU 流程自己掌握，學到最多。 | 骨架動畫、模型載入、陰影全自己寫，基礎建設吃掉大部分時間，遊戲內容會被壓縮。 |

**使用者選擇：A**（依推薦）。理由：最快玩得到東西，又真正用到 WebGPU。

- **經濟循環**：錢主要來自競技場獎金 → 買更好的武器與馬 → 挑戰更強的對手。
- **好感度來源**：除了聊天，競技場戰績（例如晉級、奪冠）也會加好感；她知道你的戰績與裝備。
- **婚後**：婚禮過場後遊戲繼續，可自由生活、繼續跟她聊天。
- **美術**：~~CC0 低多邊形中世紀素材包~~ → 已改為寫實場景＋風格化角色，見 §6.1。

## 6.1 審稿後補充的決定（使用者交由 Claude 決定：「由你發揮」）

- **好感度以規則為主、AI 微調為輔**：她有固定的喜好與禁忌清單；聊到喜好話題、送喜歡的禮物加分，踩到禁忌扣分（遊戲以關鍵詞／話題比對判定）。AI 只負責回話，並在每句 −1～+1 的小範圍內依「禮貌、用心程度」微調。不另外跑評分專用的推論，每句只做一次推論。→ 市集新增**禮品攤**。
- **內容範圍：有限、有完整結局**。目標遊玩時間約數小時：打完競技場階梯、追到她、結婚即為主線結局，婚後可繼續自由逛城聊天，但不做長期重複玩法（衛冕、隨機賽事、每日事件等留待日後）。
- **WebGPU 必備，不做 WebGL 退路**：聊天本來就需要 WebGPU；不支援時顯示清楚說明頁。畫面角落顯示目前渲染後端（WebGPU）。另外**刻意自寫至少一個 GPU 效果**：用 compute shader（TSL/WGSL）做隨風擺動的草地，讓專案確實碰到 WebGPU 本身。
- **美術方向：寫實場景＋風格化角色**（2026-11-20 使用者要求「更真實」後選定，取代原本的低多邊形卡通風）：
  - 場景（石牆、石板路、木材、屋瓦、地面）使用 **Poly Haven 的 CC0 照片掃描 PBR 材質**，天空與環境光用 Poly Haven **CC0 HDRI**。
  - 即時陰影、距離霧、環境光遮蔽（AO）、bloom、ACES 色調映射；compute shader 草地。
  - 人物與馬用品質較好的 CC0 模型（比例寫實、細節非照片級）；仍維持「只用 CC0」。
  - 設定選單加「畫質：高／中／低」（影響陰影解析度、後製開關、草量、像素比），因 GPU 同時要跑 AI 對話。
- **主角外觀固定、名字可自取**：只需一套角色骨架，武器掛點對齊這套骨架；她會用玩家取的名字稱呼，婚禮文字也帶入名字。

## 7. 遊戲內容細節

### 7.1 城鎮
- 一座有城牆的小城，配置：城門（出生點）→ 中央廣場 → 武器鋪、馬廄、競技場、城主府。
- 每棟建築門口有互動提示（例如「按 E 進入」）。武器鋪、馬廄以 UI 面板互動即可，不需完整室內；**競技場與城主府要有可走動的 3D 場地**（競技場＝圓形沙地場；城主府＝大廳，她在裡面）。
- 騎馬時不能進入建築，到門口要先下馬。

### 7.2 角色控制
- WASD 移動、滑鼠控制鏡頭、Shift 奔跑、E 互動、F 上下馬、I/Tab 開裝備畫面。
- 與建築、城牆有基本碰撞，不能穿牆。

### 7.3 武器鋪與裝備
- 販售多種武器，各有價格與數值（傷害、攻速、攻擊距離）。不同武器類型的手感要有差異（例如劍均衡、斧頭慢但痛、長柄武器距離長）。
- 買下後可在裝備畫面裝備，武器會掛在角色手上顯示。
- 裝備畫面：3D 角色預覽＋目前裝備＋擁有的物品＋擁有的馬＋金錢。

### 7.4 馬廄與馬
- 販售數匹馬，價格與速度不同、外觀（毛色）不同。
- 買下後可選一匹為「目前坐騎」，在城裡召喚／上馬騎乘；騎馬移動比跑步快。

### 7.5 競技場
- 階梯制：依序挑戰 N 位對手（例如 6～8 位），每位比前一位強（血量、攻擊力、反應、格擋機率提升），最後一位是冠軍。
- 戰鬥：左鍵揮砍、右鍵按住格擋、閃避鍵（短距離翻滾／側步，有冷卻）。雙方有血條；格擋成功不受傷（或大幅減傷）。
- 勝利領獎金並解鎖下一位；落敗不扣錢，可重新挑戰。
- 戰鬥手感（命中回饋、受擊硬直、音效）是好不好玩的關鍵，需要可調參數。

### 7.6 城主府與戀愛
- 一位成年女子（原創人物，有名字、身分、個性、喜好與禁忌），在城主府大廳。
- 走近按 E 開啟對話視窗，玩家可自由打字。
- **AI 對話**：WebLLM 載入一個中文能力好的小型指令模型（例如 Qwen 系列 1.5B～3B、q4 量化，依 GPU 能力挑選）。系統提示包含：人設、目前好感階段、玩家的戰績與裝備、最近對話摘要；要求只用正體中文、留在角色中。
- **好感度規則（由遊戲把關）**：
  - 主要加減分來自規則：喜好／禁忌話題比對、送禮（禮品攤購買，她對不同禮物喜好不同）、競技場戰績。
  - 模型每次回覆同時輸出一個微調值，遊戲限制在每句 −1～+1（見 §6.1）。
  - 每天可聊天的次數有限，或每天從聊天得到的好感有上限。
  - 競技場晉級／奪冠給額外好感。
  - 好感分階段（例如：陌生 → 熟識 → 友好 → 傾心 → 可以求婚），每階段她的態度與口吻不同。
  - 求婚需好感達最高階段（另可加條件，見 §9）；未達門檻求婚會被婉拒並小扣好感。
- **防護**：模型輸出格式錯誤、講英文／簡體、跳出角色時要有處理（重試或替換為預設回覆），不能讓遊戲壞掉。
- **載入**：模型第一次下載 1～2 GB，畫面顯示進度；下載期間城鎮、市集、競技場照常可玩，只有聊天要等。之後從瀏覽器快取載入。
- **無 WebGPU**：顯示說明頁，不進遊戲（見 §6.1）。**模型載入失敗**（例如 GPU 記憶體不足）：遊戲其他部分照常，聊天顯示清楚的錯誤訊息；是否提供簡易劇本對話見 §9。

### 7.7 婚禮與婚後
- 求婚成功 → 婚禮過場（城主府或廣場，簡單鏡頭運鏡＋文字）→ 回到自由遊玩。
- 婚後她的人設進入「妻子」階段，仍可聊天。

### 7.8 時間
- 為了「每天聊天次數」等規則，遊戲需要「天」的概念。

### 7.9 存檔（使用者確認需要）
- **自動存檔**到 IndexedDB，單一存檔槽。
- 內容：金錢、擁有的武器／禮物／馬、目前裝備與坐騎、競技場進度、好感度與階段、天數、婚姻狀態、玩家名字、她記得的對話摘要（供系統提示使用）。存檔格式帶版本號，以便日後改版遷移。
- 觸發時機：購買、換裝、競技場一場結束、對話結束、過一天、頁面隱藏／關閉（`visibilitychange` / `pagehide`）。
- 設定選單：**匯出存檔**（下載 JSON 檔）、**匯入存檔**（讀檔並驗證格式）、**刪除存檔重新開始**（需二次確認，用遊戲內 UI，不用瀏覽器 confirm 對話框）。

## 8. 技術架構（方向）

- **Vite ＋ TypeScript**，`three`（`three/webgpu` 的 WebGPURenderer，強制 WebGPU 後端）、`@mlc-ai/web-llm`。
- 自寫 WebGPU 效果：compute shader 驅動的草地（位置／擺動在 GPU 上計算）。
- 模組大致分為：場景／素材載入、角色控制、騎乘、戰鬥、經濟與物品、戀愛與對話、存檔、UI（HTML/CSS 覆蓋在 canvas 上）。
- 遊戲規則（經濟、好感度計算、戰鬥數值、對手成長）寫成與畫面無關的純邏輯模組，方便單元測試（Vitest）。
- AI 推論建議放在 Web Worker，避免卡住主執行緒。

- 求婚是否需要額外條件或道具（例如購買戒指、贏得冠軍）。
- 模型載入失敗時是否提供簡易劇本對話作為退路。

- 女子的名字與人設細節、城鎮與陣營名稱（原創）。
- 音效、音樂（同樣只用 CC0）。
